# Проверка подписки для обновлений Zapret

Небольшой Cloudflare Worker проверяет подписку на **@Slag0dworld** через Telegram-бота. Это не VPN и не прокси: трафик Zapret и переписка через него не проходят. Продакшен-зависимостей нет; Wrangler нужен только для разработки и развёртывания.

Инфраструктура проекта развёрнута в личном аккаунте владельца: D1 и Worker `https://zapret-update-membership.zapret-update-membership.workers.dev`. Деплой не запускается из этого репозитория автоматически. Бот — **@ZapretLoLBot**; подключение webhook требует локальной настройки секретов. До этого проверка закрыта. Не включайте платный тариф ради установки.

## 1. Создать бота

1. Откройте официальный [@BotFather](https://t.me/BotFather), отправьте `/newbot`.
2. Укажите имя, например `Zapret Updates`, затем свободное @имя, заканчивающееся на `bot`.
3. Сохраните выданный токен **локально**. Не присылайте его в чат, не коммитьте и не помещайте в APK. Если токен утёк, перевыпустите его в BotFather.
4. В настройках канала @Slag0dworld добавьте этого бота администратором. Для `getChatMember` Telegram гарантирует проверку других пользователей только боту-администратору. Публикация, редактирование/удаление сообщений, приглашение участников и назначение администраторов этому боту не нужны — оставьте минимальные доступные административные права.

Бот не рассылает сообщения первым: он отвечает только на запуск из приложения и кнопку проверки. Команда `/privacy` показывает краткую информацию о данных.

## 2. Создать бесплатный Worker и D1

Понадобится аккаунт Cloudflare на Workers Free и Node.js 22.13+ (для встроенных SQLite-тестов). В этой папке:

```powershell
pnpm install --frozen-lockfile
node --test
node node_modules/wrangler/bin/wrangler.js login --device --browser=false --scopes account:read user:read workers:write workers_scripts:write d1:write
node node_modules/wrangler/bin/wrangler.js d1 create zapret-update-membership
```

Эти команды нужны для собственного развёртывания форка, а не для повторного создания уже работающей базы проекта. В `wrangler.toml` замените `account_id` на свой, `database_id` — на ID новой базы, `BOT_USERNAME` — на имя своего бота **без @**. Указанные в репозитории ID не дают доступа к аккаунту владельца и не являются секретами. Для другого канала потребуется изменить закреплённый `CHANNEL_ID` также в исходниках и клиенте.

```powershell
node node_modules/wrangler/bin/wrangler.js d1 migrations apply zapret-update-membership --remote
```

Мастер настройки ниже создаст отдельный случайный webhook-секрет автоматически, без вывода на экран. Никаких платёжных данных или перехода на Paid для этого кода не требуется.

```powershell
node node_modules/wrangler/bin/wrangler.js deploy
```

Wrangler выдаст HTTPS-адрес вида `https://zapret-update-membership.<account>.workers.dev`. Этот адрес нужно закрепить в Android-сборке как `UPDATE_MEMBERSHIP_URL`; пока адрес не настроен, скачивание внутри приложения остаётся недоступным. Не делайте адрес изменяемым пользователем или получаемым из непроверенной ссылки.

Для GitHub CI задайте публичную repository variable `UPDATE_MEMBERSHIP_URL`. Сборка релиза требует этот адрес; исходный архив записывает его в `gradle.properties` как `updateMembershipUrl`, чтобы его можно было собрать с тем же значением. Ни токен бота, ни webhook-секрет в GitHub не передаются.

## 3. Подключить webhook Telegram

В PowerShell выполните мастер с реальным корневым HTTPS-адресом Worker:

```powershell
./scripts/configure-telegram.ps1 -WorkerUrl https://zapret-update-membership.<account>.workers.dev/
```

Мастер попросит токен BotFather через `Read-Host -AsSecureString` и создаст webhook-секрет автоматически. Он сверит `getMe.username` с конфигурацией и административный статус бота в канале, затем передаст значения локально установленному Wrangler через stdin, подключит webhook и сразу проверит у Telegram его точный адрес и разрешённые типы обновлений. На время настройки принудительно включается `WRANGLER_LOG_SANITIZE=true`, даже если в окружении отладочное логирование тел запросов было разрешено. Секреты не сохраняются в файлы, переменные окружения, историю команд или аргументы процессов. Не передавайте токен в `-WorkerUrl` и не отправляйте его в чат.

Если `node` не находится в PATH вашего терминала, добавьте `-NodePath 'C:/путь/к/node.exe'`. Это путь к исполняемому файлу, не секрет.

Если терминал не разрешает вставку в скрытое поле, скопируйте только токен из BotFather и запустите мастер с `-TokenFromClipboard`. Он проверит формат, немедленно очистит буфер и не выведет токен:

```powershell
./scripts/configure-telegram.ps1 -WorkerUrl https://zapret-update-membership.zapret-update-membership.workers.dev/ -TokenFromClipboard
```

Webhook принимает только `message` и `callback_query`. Скрипты не выводят секреты или Telegram URL с токеном и **не запускаются** при деплое, тестах или открытии приложения. Первичный деплой без секретов намеренно отвечает `service_not_configured`; мастер загружает их в уже опубликованный Worker. Другую программу с `getUpdates` для этого же бота одновременно использовать нельзя.

## 4. Проверить перед выпуском

1. В приложении создайте проверку подписки и откройте выданную ссылку бота. Нажмите Telegram «Запустить» — простое открытие чата не является подтверждением.
2. Без подписки бот и приложение должны отказать в обновлении.
3. Подпишитесь, нажмите «Проверить» в боте или вернитесь в приложение и проверьте снова. Скачивание должно разрешиться.
4. Отпишитесь и повторите скачивание: `authorize` проверяет членство заново, а не доверяет прошлой зелёной отметке.
5. Повторите ссылку другим аккаунтом, неправильным bearer-токеном, после 10 минут и при недоступном Telegram. Разрешения быть не должно.
6. Проверьте, что сам APK по-прежнему проходит SHA-256, проверку версии, package ID и подписи перед установкой.

Локальные тесты используют настоящую SQLite в памяти и подменяют только Telegram HTTP. Они не создают бота, базу или webhook и не расходуют облачные квоты.

## Протокол

- `POST /v1/sessions`, JSON `{ "version": "0.3.0", "nonce": "<32 случайных байта base64url без padding>" }`: `201`, `{ id, token, botUrl, expiresAt }`. ID и токен — отдельные случайные 43-символьные значения. Никаких полей `userId` не принимается.
- `GET /v1/sessions/:id` с `Authorization: Bearer <token>`: `{ status, version, nonce, expiresAt }`. `status`: `pending`, `not_member`, `verified`, `expired`. GET — только отображение результата, не допуск к скачиванию.
- `POST /v1/sessions/:id/authorize` с тем же bearer, пустым телом или `{}`: такой же ответ после **нового** `getChatMember` для Telegram ID, привязанного webhook. Клиент должен проверить точное совпадение версии и nonce, `status=verified` и срок действия непосредственно перед скачиванием. Пользовательский ID, версия, nonce и любые другие поля в этом POST запрещены.
- `POST /telegram/webhook`: только Telegram с правильным `X-Telegram-Bot-Api-Secret-Token`. Первый настоящий private `/start <id>` атомарно привязывает аккаунт. Кнопка `check:<id>` работает только для этого же аккаунта.
- `GET /health`: доступность HTTP обработчика; не доказывает, что D1, бот и webhook правильно настроены.

Все времена — Unix seconds. Сессия и подтверждение живут не более 10 минут от создания. После удаления сессии bearer даёт `401`; до очистки логически истёкшая сессия отвечает `expired`. Неправильный bearer — `401`, лишние поля — `400`, недоступность Telegram — `503`, лимит или параллельная проверка — `429` с `Retry-After`. Последняя допускает короткий повтор, но никогда не разрешает скачивание.

У API нет wildcard CORS; запросы с `Origin` отклоняются. В production нужен закреплённый HTTPS-адрес. Токен бота используется только на сервере. В базе хранится SHA-256 bearer-токена, не его исходное значение. Подтверждение не является DRM: APK, опубликованный открыто на GitHub или в Telegram, всё равно можно скачать вручную. Проверяется доступ к кнопке обновления в обычном приложении, а не право запускать программу.

## Данные, стоимость и ограничения

В рабочей D1-базе временно находятся session ID, хеш bearer, версия, nonce, Telegram numeric ID и статус подписки. Имена, телефоны, сообщения, история просмотра и трафик не сохраняются. Истёкшие записи удаляются при создании новой сессии и cron-очисткой каждые 10 минут; сбой очистки не продлевает допуск. Облачные резервные копии D1 могут сохранять удалённые данные согласно политике Cloudflare. Это не анонимная авторизация: Telegram и Cloudflare участвуют в проверке.

Приложение и Worker не пишут в логи токены, тела запросов, IP или Telegram ID. Автоматическая observability выключена в конфигурации. Не включайте `wrangler tail` или дополнительные журналы с содержимым запросов на реальных пользователях. Cloudflare всё равно обрабатывает сетевые метаданные на своей стороне.

Для защиты от случайных повторов лимиты на IP: создание 5/мин, GET 60/мин, свежая авторизация 6/мин. Команды `/start`, `/privacy` и callback-проверки делят отдельный лимит 10/мин на настоящий аккаунт Telegram; он применяется до привязки сессии, проверок членства и ответов бота. Превышение webhook-лимита подтверждается HTTP 200 без Telegram-запросов, чтобы не провоцировать повторную доставку. IP и Telegram ID не хранятся в ключах лимитов: ключ — HMAC от источника, действия и текущей минуты, с коротким сроком жизни. Общий предел — 5000 активных сессий. Эти лимиты не заменяют edge-защиту от распределённого DDoS и не гарантируют отсутствие исчерпания бесплатной квоты. За одним общим NAT лимит создания делится между пользователями.

На дату подготовки кода [Workers Free](https://developers.cloudflare.com/workers/platform/pricing/) включает 100 000 запросов/день и 10 мс CPU на запрос; [D1 Free](https://developers.cloudflare.com/d1/platform/pricing/) — 5 млн прочитанных и 100 000 записанных строк/день, 5 ГБ суммарно. Одна проверка использует несколько запросов и записей, поэтому это **не** 100 000 обновлений/день. Проверяйте актуальные лимиты и метрики перед выпуском. При исчерпании Free сервис откажет в проверке; автоматического перехода на платный тариф здесь нет.

Официальные справки: [Telegram Bot API / getChatMember и webhook](https://core.telegram.org/bots/api), [секреты Workers](https://developers.cloudflare.com/workers/configuration/secrets/), [D1 prepared statements](https://developers.cloudflare.com/d1/worker-api/prepared-statements/), [миграции D1](https://developers.cloudflare.com/d1/reference/migrations/).
